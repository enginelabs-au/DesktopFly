# 05 · Provider economics, native adapters, multi-repo operation

**Review copy:** procedures below specify future implementation; the current request authorizes document revision only. See [index](INDEX.md).

Read when: R3 or R4 after the loading experiment is accepted. Implementation candidates, not installed infrastructure. Return to [index](INDEX.md). Source/version verification: [08](08-EVIDENCE.md); historical numeric comparisons: [09](09-HISTORICAL-EVIDENCE-AND-COVERAGE.md).

**Economics first.** Keep the user-stated US$248/month baseline. Optimize useful work within existing allowances before new spend. Track account quota separately from marginal cash. A fixed-price subscription may yield no immediate cash saving from fewer tokens while improving capacity/latency. Conversely, routing through an API may add cash cost despite owning a chat subscription. Verify native CLI/headless support, authentication, billing route and terms per account. Never repurpose consumer credentials as a generic gateway token.

After the lean baseline stabilizes, evaluate whether a different plan satisfies measured volume. Historical scenarios: replacing the US$200 Cursor tier with US$60 yields US$108 combined; US$20 yields US$68; differences US$140/180 before taxes/overages/allowance changes. These are arithmetic scenarios, not downgrade recommendations or throughput guarantees. If a subscription adds no demonstrated value, evaluate removing the expense rather than inventing work for it. All account changes need explicit authorization.

**Role aliases, not permanent provider personalities.** Define `scout`, `executor`, `escalation`, `reviewer` with configurable model/reasoning/tool mappings. Inspect actual inheritance, especially subagents. Start with a capable ordinary model; cheaper retrieval only where it succeeds; high effort/frontier escalation when ambiguity, repeated failure or consequences justify it. A model's self-confidence is insufficient routing evidence. Cap retries, diagnose failure cause, then escalate; one repair attempt is an initial policy candidate, not a universal optimum or user-approved dollar budget.

Observed 2026-09-17: the `codex` CLI binary is broken (missing vendored executable) while the Codex desktop configuration defaults to `gpt-6-astra` at `ultra` effort; Claude Code has no global `CLAUDE.md`, rules, skills or agents; Gemini CLI has an empty `GEMINI.md`; the Cursor CLI's print mode required a fresh login. There is currently nothing to consolidate in R3; adapters would be new work, not cleanup. Cursor is the primary existing harness; evaluate economical native routes against available third-party routes after R1. Codex/ChatGPT and Claude are alternative executors or reviewers, not obligatory serial steps. Gemini free is useful for bounded public research/evidence challenges when its available model suffices. OpenCode is an optional harness with variable free/API endpoints, not guaranteed free frontier inference. VS Code is an editor/host choice. Never assign “Gemini plans, GPT thinks, Claude codes” as an untested permanent hierarchy.

**Historical candidates.** Earlier research considered Composer 2.5 for routine Cursor work; Terra/medium or Sonnet for ordinary coding; Luna/Haiku for bounded scouts; Sol/Opus for more demanding work; Astra/Fable for exceptional escalation. These names are dated hypotheses, not current account availability or fixed configuration. Resolve exact supported IDs in the chosen client, then evaluate. Keep model/effort unchanged during loading-policy comparisons. Route-specific rates, cache behavior, tokenization, thinking output and quota accounting can reverse apparent list-price rankings.

**Native adapter contract.** Each adapter identifies supported client/version, source policy hash, actual discovery path/scope, precedence, import behavior, schema, permissions, reload procedure, positive/negative activation check and unmanaged-file preservation. Do not simply rename `.cursor` or symlink entire configuration trees. An import may eagerly concatenate everything; a symlink may loop or be undiscovered. Changes in policy and adapter must update the same managed version atomically where feasible; fail visibly on collision.

- **Cursor:** native `.cursor/rules/*.mdc`, root/nested `AGENTS.md`, discovered skills/agents and supported user settings/UI controls. Keep global preferences minimal. A conceptual capability profile is not necessarily a native selectable profile. Verify installed build and use documented mechanisms; do not invent JSON keys. Headless automation, if adopted, must verify write permissions and account support; never make unrestricted execution flags a default.
- **Codex:** use the documented global/project instruction hierarchy and supported skill discovery. Current official sources describe `~/.codex/AGENTS.md`, repository guidance and custom agent configuration. Verify current schema and effective settings before authoring TOML; specify worker model/effort where cost control depends on it. Native subagents are not automatic worktrees or guaranteed distinct security boundaries. [Instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [skills](https://learn.chatgpt.com/docs/build-skills), [subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).
- **Claude Code:** a small `CLAUDE.md` may import the small canonical contract; imports are not lazy merely because files are separate. Use native path-scoped rules, explicit agent tool/model bounds and deliberate manual skills. Confirm metadata/body/preload behavior, available context/usage diagnostics and current Explore inheritance. Programmatic budget flags do not automatically enforce aggregate pipeline spend. [Memory](https://code.claude.com/docs/en/memory), [skills](https://code.claude.com/docs/en/skills), [agents](https://code.claude.com/docs/en/sub-agents), [costs](https://code.claude.com/docs/en/costs).
- **Gemini CLI:** choose one canonical context filename strategy or a tiny `GEMINI.md` adapter. Verify ancestor/component discovery and actual concatenated context via supported diagnostics. A browser chat has no local filesystem access simply because paths appear in a prompt. Supply selected sanitized artifacts when remote. API model economics do not establish access on a free consumer account. [Context](https://geminicli.com/docs/cli/gemini-md/), [agents](https://geminicli.com/docs/core/subagents/).
- **OpenCode:** use its native config, per-agent models/permissions and narrowly enabled MCPs. `small_model` is not proof of an automatic implementation router; step limits are not dollar caps. Compaction/pruning is deliberate and source/checkpoint recoverability must survive. Verify provider namespace, endpoint availability and data terms before any confidential task. [Config](https://opencode.ai/docs/config/), [agents](https://opencode.ai/docs/agents/), [MCP](https://opencode.ai/docs/mcp-servers/), [Zen](https://opencode.ai/docs/zen/).
- **VS Code:** follow the selected agent harness's native customization/discovery/permission system. Editor settings are not portable agent policy. [Customization](https://code.visualstudio.com/docs/agent-customization/overview).
- **Hermes/OpenClaw:** select at most one only if channels, schedules, remote routing or durable identities justify it. Separate writable agent state and explicit shared artifacts. Do not replicate the same coding policy across persona/user/memory/instruction files. [Hermes profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles/), [OpenClaw routing](https://docs.openclaw.ai/concepts/multi-agent).

**Workflow routes.** Routine fix: one brief, executor, focused checks. Ambiguous feature: targeted investigation, acceptance criteria, one implementation owner, consequential review. Cross-repo change: contract/dependency map, isolated workers, dependency-ordered integration. High-consequence auth/data/release work: appropriate strong executor, independent review and relevant integration checks; free-first is not a requirement. Mechanical chores: script/codemod before model. Research: bounded question/source packet with disagreements retained. Repeated operations: event/CI/deterministic polling; invoke a model only on actionable change, not an expensive heartbeat to discover no change.

**Repository topology.** Central configuration/coordinator may live outside projects; workers launch inside the selected repo/worktree. Global preferences do not require a home-directory working tree. Maintain a registry only for actual needed projects: stable ID, verified absolute path, canonical remote, owner, commands, adapter revision, allowed related repos and dependency/interface references. Paths are local implementation data, not automatic read/write authority.

Interface cards contain exported API/schema/contract, producer revision/hash, consumer versions, compatibility constraints, relevant source paths and verification command. They do not repeat entire repository architecture. Retrieve neighboring cards/source case by case; invalidate on relevant diff/hash changes. CI or deterministic scripts can maintain drift checks. Avoid daily LLM rewrites of every project summary. Validate revision/current worktree before trusting cached cards.

**One entry point, bounded processes.** Use supported native command/CLI workflows first. If absent, a small local runner can select cwd/profile, invoke native agent processes, persist structured state and collect evidence; it need not reimplement their tool loops. `agentctl` or similar names are conceptual until a tested binary/script exists. Suggested layout (names not native schema): `registry/`, `adapters/`, `schemas/`, `scripts/`, `evals/`. Preserve useful existing structure; do not reorganize merely for aesthetics.

Runner state: task ID; objective/non-goals; repo/base SHA; branch/worktree; allowed paths/effects; acceptance; selected profile/provider/model/effort; budget/attempts/deadline; capability/evidence refs; owner; artifact locations; status; next action. States: intake → prepared → executing → verifying → review-if-needed → ready/integrated; failures → bounded repair/escalate/checkpoint. Persist transitions before external effects where necessary; idempotency keys and receipts prevent duplicate submission on resume.

**Concurrency and accounting.** One writer per working tree, independent worktrees for concurrent changes, one integration owner. Lock resources that really conflict. Worktrees do not isolate ports, databases, processes, credentials or remote effects. Authenticate/permit each worker appropriately; filesystem cwd alone is not a sandbox. Aggregate in-flight spend/reservations, not just completed invoices; quota usage may be unavailable. Enforce budgets/timeouts/retry/delegation depth externally when feasible. Otherwise disclose soft limits; do not claim prose is a hard cap. Recovery must preserve dirty work and reconcile actual process/external status before retrying.

**Conditional rollout.** Add only adapters the user actually uses. Demonstrate one generic onboarding path, one real cross-repo contract and one resume/failure case before expanding. Backups/source manifests/drift tests are preferable to a second policy bureaucracy. No message bus, vector database, orchestration framework or global memory service without a measured need unmet by native workflows and files. Gate R3/R4 on demonstrated benefit and maintainability, not feature inventory.
